# QuickNotes - Complete File Structure Guide

## 📁 Project Overview
This document explains the role and purpose of every file in the QuickNotes application.

---

## 🏗️ Root Configuration Files

### **Package & Dependencies**
- **`package.json`** - Defines project dependencies, scripts, and metadata
- **`pnpm-lock.yaml`** - Locks exact versions of all dependencies (generated by pnpm)
- **`.npmrc`** - pnpm configuration (enables build scripts for Prisma, etc.)

### **TypeScript Configuration**
- **`tsconfig.json`** - TypeScript compiler settings and path aliases (@/* imports)
- **`next-env.d.ts`** - Next.js TypeScript definitions (auto-generated)

### **Next.js Configuration**
- **`next.config.ts`** - Next.js app configuration (build settings, redirects, etc.)
- **`middleware.ts`** - Route protection middleware (checks authentication before accessing protected pages)

### **Styling Configuration**
- **`postcss.config.mjs`** - PostCSS configuration for TailwindCSS processing
- **`eslint.config.mjs`** - ESLint rules for code quality and style checking

### **Vercel Deployment**
- **`vercel.json`** - Vercel deployment configuration (build commands, environment settings)

### **Docker Configuration**
- **`Dockerfile`** - Instructions to build Docker container image
- **`docker-compose.yml`** - Multi-container Docker setup (app + MongoDB)
- **`.dockerignore`** - Files to exclude from Docker builds
- **`.env.docker.example`** - Example environment variables for Docker

### **Environment Variables**
- **`.env`** - Local environment variables (DATABASE_URL, NEXTAUTH_SECRET, etc.) - **NEVER commit this!**
- **`.env.example`** - Template showing required environment variables (safe to commit)

### **Git Configuration**
- **`.gitignore`** - Files/folders to exclude from version control (.env, node_modules, etc.)

### **shadcn/ui Configuration**
- **`components.json`** - Configuration for shadcn/ui components (styling, aliases, etc.)

## 📂 `/app` - Next.js App Router (Pages & Routes)

### **Root Layout & Landing Page**
- **`app/layout.tsx`** - Root HTML structure, global providers, metadata, dark mode setup
- **`app/page.tsx`** - Landing page with hero section, features, CTA buttons
- **`app/globals.css`** - Global styles, TailwindCSS imports, custom animations
- **`app/favicon.ico`** - Browser tab icon

### **Authentication Pages**
- **`app/login/page.tsx`** - Login form with email/password authentication
- **`app/register/page.tsx`** - Registration form for new users

### **Dashboard (Protected Route)**
- **`app/dashboard/page.tsx`** - Main dashboard (server component) - fetches user's notes from DB
- **`app/dashboard/loading.tsx`** - Loading skeleton shown while dashboard data loads

### **Profile (Protected Route)**
- **`app/profile/page.tsx`** - User profile page (server component) - shows user info and note feed
- **`app/profile/loading.tsx`** - Loading skeleton for profile page

### **Note Editor (Protected Route)**
- **`app/notes/[id]/page.tsx`** - Individual note editing page (dynamic route)
- **`app/notes/[id]/loading.tsx`** - Loading skeleton for note editor

### **Shared Notes (Public Route)**
- **`app/shared/[token]/page.tsx`** - Public note sharing via token (read-only)

## 🔌 `/app/api` - API Routes (Backend Endpoints)

### **Authentication**
- **`app/api/auth/[...nextauth]/route.ts`** - NextAuth.js API handler (login/logout/session)

### **Categories & Templates**
- **`app/api/categories/route.ts`** - CRUD operations for note categories
- **`app/api/categories/[id]/route.ts`** - Individual category operations
- **`app/api/templates/route.ts`** - Note templates management

- **`app/api/debug/route.ts`** - Environment check endpoint (shows if env vars are set)

## 🔄 Data Flow Architecture

### **1. User Authentication Flow**
```
User → Login Page (app/login/page.tsx)
     → API Route (app/api/auth/[...nextauth]/route.ts)
     → Auth Library (lib/auth.ts)
     → Prisma (lib/prisma.ts)
     → MongoDB Atlas
     → Session Token (JWT)
     → Redirect to Dashboard
```

### **2. Note Creation Flow**
```
User → Dashboard (app/dashboard/page.tsx)
     → Create Dialog (components/notes/create-note-dialog.tsx)
     → API Route (app/api/notes/route.ts - POST)
     → Prisma (lib/prisma.ts)
     → MongoDB Atlas
     → Refresh Dashboard
```

### **3. Note Editing Flow**
```
User → Note Card Click (components/notes/note-card.tsx)
     → Note Editor Page (app/notes/[id]/page.tsx)
     → Editor Component (components/notes/note-editor-client.tsx)
     → TipTap Editor (components/editor/tiptap-editor.tsx)
     → Save → API Route (app/api/notes/[id]/route.ts - PUT)
     → Prisma → MongoDB Atlas
```

## 🎯 Key File Relationships

### **Server Components (Fetch Data)**
- `app/dashboard/page.tsx` → Fetches notes from DB
- `app/profile/page.tsx` → Fetches user + notes from DB
- `app/notes/[id]/page.tsx` → Fetches single note from DB

### **Client Components (Interactive UI)**
- `components/notes/dashboard-client.tsx` → Search, create, delete
- `components/notes/note-editor-client.tsx` → Edit, save, tags
- `components/auth/profile-client.tsx` → Profile display

### **API Routes (Backend Logic)**
- All `/app/api/**` files handle HTTP requests (GET, POST, PUT, DELETE)
- Use Prisma to interact with MongoDB
- Return JSON responses

### **Shared Components**
- `components/ui/**` → Used everywhere (buttons, cards, inputs)
- `components/notes/note-card.tsx` → Used in dashboard & profile

## 🔐 Protected vs Public Routes

### **Public Routes** (Accessible without login)
- `/` - Landing page
- `/login` - Login page
- `/register` - Registration page
- `/shared/[token]` - Shared notes (read-only)

### **Protected Routes** (Require authentication - via `middleware.ts`)
- `/dashboard` - User dashboard
- `/profile` - User profile
- `/notes/[id]` - Note editor
- All `/api/**` routes (except `/api/auth/**` and `/api/register`)

## 💡 Quick Reference

**Need to add a new page?** → Create file in `/app` folder  
**Need a new API endpoint?** → Create file in `/app/api` folder  
**Need a new component?** → Create file in `/components` folder  
**Need to change database schema?** → Edit `prisma/schema.prisma` → Run `pnpm prisma db push`  
**Need to add environment variable?** → Add to `.env` AND `.env.example` AND Vercel dashboard  
**Need to change auth logic?** → Edit `lib/auth.ts`  
**Need to protect a route?** → Add to matcher in `middleware.ts`
